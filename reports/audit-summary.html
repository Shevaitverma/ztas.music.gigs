The Go migration

Planned, stress-tested, declined

You asked for a full backend rewrite in Go. I planned it properly, then had four specialists attack the plan. All four returned “not safe to execute as written” — and the reasons were worth more than the plan itself.

The clearest example: the codebase has zero explicit database ID conversions in 18,000 lines — it relies entirely on a convenience the JavaScript library provides and Go does not. Go wouldn't error on this. It would silently match nothing. The practical effect is that the “must beat the current lowest bid” rule quietly disappears, and an artist wins the auction at the maximum budget. Your core mechanic, defeated by a type conversion, invisible to every test in the plan.

Ten more corrections of that kind are on record, and the honest timeline came back at roughly double my first estimate — about 32 engineer-weeks, or 24–28 calendar weeks.

Decision: stay on TypeScript. The backend's language was never the problem. Spending six months rewriting working code would have delayed the payment layer by six months and reset the security work that just landed. Cleanup instead — which is where the repo is now.
